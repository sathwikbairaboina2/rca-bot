> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Record progress in the ledger `.superpowers/sdd/2026-10-04-rca-bot/progress.md` after every task, using the format shown at the top of that file.

**Goal:** Ship v0.1 of rca-bot, an alarm-to-root-cause bot:
- the model picks Logs Insights queries from a typed catalog and drafts hypotheses;
- a deterministic verifier drops any hypothesis whose citations are not verbatim in the stored results;
- a Block Kit card is posted.

A seeded simulator runs the real demo-service code under 5 labelled chaos faults, so accuracy is a measured number. The CDK app synthesizes the AWS shape: EventBridge → Step Functions → Lambdas.

**Architecture:** One ESM TypeScript package (ADR 0001):
- `src/core` is pure logic: the Logs Insights subset engine, the catalog, the verifier, confidence and redaction.
- `src/steps` holds the investigation steps, with injected ports.
- `src/pipeline/investigate.ts` runs those steps in-process. It is used by the `demo` and `eval` CLI commands.
- `src/handlers` holds thin Lambda wrappers around the same steps.
- `infra/` is the CDK app.

Lambda code is prebundled with esbuild.

## Review Focus

These input classes are the ones a happy-path test would miss. Each has tests in the task that owns it.

1. **Fabricated, near-miss and type-confused citations.** Cover these: one changed character, a different case, a trailing space, a numeric quote `17` against the string `"17"` (must pass), `17.0` against `"17"` (must fail), a row index of `-1`, `1.5` or out of range, an unknown queryId, a failed query, an empty quote, and a quote of a field missing from the row. (Task 5)
2. **Query injection.** `filterValue` values with `"`, `|`, a backtick, a newline, `\`, `/regex/`, `filter 1=1`, more than 80 characters, or an empty string. Also: unknown template ids, log groups outside the allowlist, extra keys, and more than 5 log groups. (Task 4)
3. **Alarm storms and races.** 5 concurrent alarm events for the same service produce exactly one investigation and exactly 2 model calls. An `OPEN` item whose window has expired lets a new incident open. (Tasks 9, 10, 18)
4. **Malformed model output.** Non-JSON, JSON that fails the schema, a category outside the enum, an empty `hypotheses` list, and a model error or timeout. Each must retry once, then end inconclusive or use the fallback plan. The run must never crash. (Tasks 13, 14)
5. **Hostile log content.** A log message containing `<script>` must be escaped in the Slack sink HTML. Emails and card-like numbers must be redacted before the model sees them. A log line that is not JSON must not crash field discovery. (Tasks 3, 6, 17)

**Grammar** (keywords are case-insensitive, and identifiers keep their case):
```
query    := command ( '|' command )*
command  := 'fields' fieldList
          | 'filter' expr
          | 'stats' agg ( ',' agg )* ( 'by' fieldList )?
          | 'sort' field ( 'asc' | 'desc' )?          -- default asc
          | 'limit' INT                                -- 1..10000
fieldList := field ( ',' field )*
field    := '@'? IDENT                                 -- IDENT = [A-Za-z_][A-Za-z0-9_.]*
agg      := FN '(' ( '*' | field ) ( ',' NUMBER )? ')' ( 'as' IDENT )?
FN       := count | sum | avg | min | max | pct        -- pct requires the NUMBER (0 < p <= 100); others forbid it; only count allows '*'
expr     := and ( 'or' and )*
and      := unary ( 'and' unary )*
unary    := 'not' unary | primary
primary  := '(' expr ')'
          | 'ispresent' '(' field ')'
          | field CMP literal                          -- CMP = '=' | '!=' | '<' | '<=' | '>' | '>='
          | field 'like' STRING
          | field 'in' '[' literal ( ',' literal )* ']'
literal  := STRING | NUMBER                            -- STRING: "..." or '...' with \" \' \\ escapes; NUMBER: -?\d+(\.\d+)?
```
Anything else is a parse error. That includes regex literals `/.../`, backticks, `display`, `parse`, `dedup`, newlines inside strings, and trailing tokens.

**AST** (export these types):
```ts
export type Literal = string | number;
export type Expr =
  | { kind: "and" | "or"; left: Expr; right: Expr }
  | { kind: "not"; expr: Expr }
  | { kind: "cmp"; field: string; op: "=" | "!=" | "<" | "<=" | ">" | ">="; value: Literal }
  | { kind: "like"; field: string; value: string }
  | { kind: "in"; field: string; values: Literal[] }
  | { kind: "ispresent"; field: string };
export interface Agg { fn: "count" | "sum" | "avg" | "min" | "max" | "pct"; arg: string; p?: number; as: string }
export type Command =
  | { kind: "fields"; fields: string[] }
  | { kind: "filter"; expr: Expr }
  | { kind: "stats"; aggs: Agg[]; by: string[] }
  | { kind: "sort"; field: string; dir: "asc" | "desc" }
  | { kind: "limit"; n: number };
export class InsightsParseError extends Error { constructor(message: string, readonly position: number) { super(message); this.name = "InsightsParseError"; } }
export function parseQuery(query: string): Command[];
```
When there is no `as`, the default agg name is the canonical text: `count(*)`, `count(@initDuration)`, `pct(@duration, 99)`, `avg(durationMs)`.

**Semantics:**
- **`discoverFields(e)`** returns a record with:
  - `@timestamp`: `formatInsightsTimestamp(e.timestamp)`;
  - `@message`: `e.message`;
  - `@logStream`: `e.logStream`;
  - `@log`: `e.logGroup`. AWS prefixes the account id; we do not. Note this in the comment.
  - every entry of `e.fields`;
  - when `e.message` parses as a JSON **object**, every primitive leaf. Nested objects are flattened with `.`, for example `{"a":{"b":1}}` gives `a.b`. Arrays are skipped, and booleans become `"true"`/`"false"`.

  When the message does not parse, it must not throw: the record keeps only the system fields.
- **`filter`:**
  - `cmp`: if the literal is a number and the field value is numeric (`Number(v)` is finite and the value is not `""`), compare as numbers. Otherwise `=`/`!=` compare `String(v)` with `String(literal)`, and `<`/`>` compare strings lexicographically.
  - **A missing field makes every `cmp`, `like` and `in` false, including `!=`.**
  - `like`: case-sensitive substring of `String(v)`.
  - `in`: any element satisfies the `=` rule.
  - `ispresent`: the field is present and not `""`.
  - `not`: logical negation.
- **`fields f1, f2`:** project each record onto those fields, dropping missing ones.
- **`stats`:**
  - group by the `by` fields. The group key is a JSON array of the values, with missing values as `null`. Each output row holds the by-fields that are present plus the aggs.
  - `count(*)` counts records. `count(f)` counts the records where `f` is present.
  - `sum`, `avg`, `min` and `max` work over the present numeric values. When there are none, the agg is omitted from the row.
  - `pct(f,p)` is nearest-rank over the sorted numeric values: `idx = Math.ceil(p/100 * n) - 1`, clamped to `[0, n-1]`.
  - Output rows are in first-seen group order.
- **`sort f dir`:** a stable sort. It is numeric when both values are numeric, otherwise it compares strings. Missing values sort last in both directions.
- **`limit n`:** take the first n.
- **Final output:** when the query has no `fields` and no `stats` command, project each record to `@timestamp`, `@message`. Convert every value to a string:
  - integers as `String(n)`;
  - other numbers as `String(Number(n.toFixed(3)))`;
  - strings unchanged.
- **Export:** `evaluateQuery(query: string | Command[], events: LogEvent[]): Row[]`. The caller has already filtered the events by log group and window.

```ts
import { computeConfidence } from "./confidence.js";
import { isCategory, type DroppedHypothesis, type Evidence, type Hypothesis, type QueryResult, type VerifiedHypothesis } from "./types.js";

export interface Verdict { verified: VerifiedHypothesis[]; dropped: DroppedHypothesis[] }

export function checkEvidence(ev: Evidence, byId: Map<string, QueryResult>): string | null {
  const q = byId.get(ev.queryId);
  if (!q) return `unknown queryId ${ev.queryId}`;
  if (q.status !== "Complete") return `query ${ev.queryId} did not complete (${q.status})`;
  if (!Number.isInteger(ev.row) || ev.row < 0 || ev.row >= q.rows.length) return `row ${ev.row} out of range for ${ev.queryId}`;
  const keys = Object.keys(ev.quote ?? {});
  if (keys.length === 0) return `empty quote for ${ev.queryId} row ${ev.row}`;
  const row = q.rows[ev.row]!;
  for (const k of keys) {
    if (!Object.prototype.hasOwnProperty.call(row, k)) return `field ${k} not in ${ev.queryId} row ${ev.row}`;
    const v = ev.quote[k];
    if (typeof v !== "string" && typeof v !== "number") return `non-scalar quote for ${k}`;
    if (String(v) !== row[k]) return `value mismatch for ${k} in ${ev.queryId} row ${ev.row}`;
  }
  return null;
}

export function verifyEvidence(hypotheses: readonly Hypothesis[], results: readonly QueryResult[]): Verdict {
  const byId = new Map(results.map((r) => [r.queryId, r]));
  const verified: VerifiedHypothesis[] = [];
  const dropped: DroppedHypothesis[] = [];
  for (const h of hypotheses) {
    let reason: string | null = null;
    if (!isCategory(h.category)) reason = `unknown category ${String(h.category)}`;
    else if (h.category === "UNKNOWN") reason = "UNKNOWN is not a root cause";
    else if (!Array.isArray(h.evidence) || h.evidence.length === 0) reason = "no evidence";
    else for (const ev of h.evidence) { reason = checkEvidence(ev, byId); if (reason) break; }
    if (reason || !isCategory(h.category)) { dropped.push({ hypothesis: h, reason: reason ?? "invalid" }); continue; }
    verified.push({ rank: verified.length + 1, category: h.category, summary: h.summary, evidence: h.evidence, confidence: computeConfidence(h.evidence) });
  }
  return { verified, dropped };
}

### Task 10: DynamoDB incident store

**Files:**
- Create: `src/ports/dynamoIncidentStore.ts`
- Test: `test/ports/dynamoIncidentStore.test.ts`

`DynamoIncidentStore implements IncidentStore`. It is constructed with `{ doc: DynamoDBDocumentClient; tableName: string }` and uses a single table with `pk`/`sk` and the TTL attribute `expiresAt`, in **epoch seconds**. The item shapes come from ADR 0006:

- **`openIncident`**: one `TransactWriteCommand` with:
  1. a Put of `{pk:"SVC#<service>", sk:"OPEN", incidentId, expiresAt: ceil((now+window)/1000)}`, with `ConditionExpression: "attribute_not_exists(pk) OR expiresAt < :nowSec"`;
  2. a Put of `{pk:"INC#<id>", sk:"META", service, alarms, openedAt: ISO, status, expiresAt: now+30d}`;
  3. a Put of `{pk:"INC#<id>", sk:"BUDGET", queriesAllowed, queriesUsed:0, bytesScanned:0, tokensIn:0, tokensOut:0, expiresAt}`.

  When the transaction fails with `TransactionCanceledException` and `CancellationReasons[0].Code === "ConditionalCheckFailed"`, do a `GetCommand` on `SVC#<service>/OPEN` (`ConsistentRead: true`) and return `{opened:false, incidentId}`. Rethrow any other error.
- **`appendAlarm`**: an `UpdateCommand` on META, `SET alarms = list_append(if_not_exists(alarms, :empty), :a)`.
- **`consumeQueries`**: up to 5 tries of:
  1. a `GetCommand` on BUDGET (consistent);
  2. `grant = min(n, allowed - used)`. Return 0 when the grant is 0 or less;
  3. an `UpdateCommand` with `SET queriesUsed = :new` and `ConditionExpression: "queriesUsed = :seen"`. When it fails with `ConditionalCheckFailedException`, retry.

  After 5 tries, return 0.
- **`addUsage`**: an `UpdateCommand` with `ADD tokensIn :i, tokensOut :o, bytesScanned :b`.
- **`reserveDailyTokens`**: an `UpdateCommand` on `{pk:"DAY#<day>", sk:"TOKENS"}` with `ADD used :n SET expiresAt = :exp` and `ConditionExpression: "attribute_not_exists(used) OR used <= :limit"`, where `:limit = cap - n`. A `ConditionalCheckFailedException` returns false.
- **`setStatus`**: an `UpdateCommand` on META, `SET #s = :s`.
- **`saveHypotheses`**: a `PutCommand` per verified hypothesis, `HYP#<rank>` with `verified: true`, and per dropped one, `HYP#X<i>` with `verified: false, droppedReason`.
- **`getIncident`**: a `QueryCommand` on `pk = :p`. Map META and BUDGET back, and return null when META is missing.

  store: IncidentStore; results: ResultsStore; runner: QueryRunner; model: Model;
  poster: SlackPoster | null; context: ContextSource;
  now: () => number; newId: () => string;
  config?: Partial<DedupeConfig>; serviceOf?: (alarmName: string) => string;
}
export async function stageDedupe(rawEvent: unknown, deps: PipelineDeps): Promise<DedupeDecision>;
export async function stagePlan(incidentId: string, ctx: InvestigationContext, deps: PipelineDeps): Promise<{ planned: PlannedQuery[]; outcome: PlanOutcome; notes: string[] }>;
export async function stageHypothesize(incidentId: string, ctx: InvestigationContext, results: QueryResult[], deps: PipelineDeps): Promise<HypothesizeOutcome>;
export async function stageVerify(incidentId: string, hyps: Hypothesis[], results: QueryResult[], deps: PipelineDeps): Promise<{ verdict: Verdict; status: "POSTED" | "INCONCLUSIVE" }>;
export async function stagePost(report: IncidentReport, deps: PipelineDeps): Promise<{ location: string | null; note?: string }>;
export async function investigate(rawEvent: unknown, deps: PipelineDeps): Promise<IncidentReport>;
```
- **`stageDedupe`** = `parseAlarmStateChange(rawEvent, serviceOf)`, then `dedupeAndBudget`.
- **`stagePlan`:**
  1. `planQueries(ctx, model)`, then `addUsage(tokens)`.
  2. `granted = consumeQueries(id, selections.length)`.
  3. `planned = selections.slice(0, granted).map((s, i) => planQuery("q" + (i+1), s, ctx.window))`.
  4. When `granted < selections.length`, add the note `query budget capped: requested <n>, running <granted>` (I3).
- **`stageHypothesize`** = `hypothesize`, then `addUsage`.
- **`stageVerify`** = `verifyEvidence`, then `saveHypotheses` and `setStatus`.
- **`stagePost`** renders the card and posts it. A poster error is caught and returned as the note `slack post failed: <msg>`. When the poster is null, the location is null.
- **`investigate`** runs:
  1. `stageDedupe`. On `IGNORE`/`SUPPRESS`, return a report with status `SUPPRESSED` (or `INVESTIGATING` for IGNORE, with the note `ignored non-ALARM state`), `context: null` and `modelCalls: 0`, and post nothing. On `BUDGET_EXHAUSTED`, build the report with that status, post the budget card and return.
  2. `ctx = await deps.context.gather(alarm)`.
  3. `stagePlan`.
  4. `runQueries` with concurrency 3. Add the summed `bytesScanned` with `addUsage`.
  5. `stageHypothesize`.
  6. `stageVerify`.
  7. Assemble the `IncidentReport`, `stagePost`, and return the report.

  `modelCalls` = plan calls + hypothesize calls. `usage` is the sum. `notes` are concatenated.

### Task 20: The eval harness and the fabrication bench

**Files:**

**`score.ts`:** `scoreRun(report: IncidentReport, truth: GroundTruth)` returns `{ top1: boolean; top2: boolean; inconclusive: boolean; unverifiedPosted: number }`:
- `top1 = posted[0]?.category === truth.category`;
- `top2` = truth is among `posted[0..1]`;
- `inconclusive = posted.length === 0`;
- `unverifiedPosted = verifyEvidence(posted, report.queries).dropped.length`. This **re-verifies what was actually posted**, independently of the pipeline's own verdict.

**`runEval.ts`:**
```ts
export interface EvalOptions { modelSpec: string; scenarioIds: string[] | "all"; repeat: number; outFile: string; model?: Model; onRun?: (r: EvalRun, i: number, total: number) => void; env?: NodeJS.ProcessEnv }
export interface EvalRun { scenarioId: string; seed: number; expected: Category; status: IncidentStatus | "ERROR"; postedCategories: Category[]; top1: boolean; top2: boolean; inconclusive: boolean; unverifiedPosted: number; dropped: number; modelCalls: number; inputTokens: number; outputTokens: number; queriesRun: number; ms: number; notes: string[]; error?: string }
export async function runEval(o: EvalOptions): Promise<EvalReport>;
```
- **Loop:** for each repeat `r` in `0..repeat-1` and each scenario (sorted by id), use `seed = 1000 + r`, then:
  1. simulate;
  2. pick the expected alarm event;
  3. build fresh memory stores with `poster: null`;
  4. use `now` = the alarm time;
  5. run `investigate`, timing it with `performance.now()`;
  6. score the run.

  A thrown error gives a run with `status: "ERROR"`, every boolean false and `error` set. The loop always continues.
- **Output:** after **every** run, rewrite `outFile` (with `mkdir -p`) as pretty JSON:
  ```
  { schema: 1, env: "local-fixture", model, startedAt, updatedAt, complete, runsPlanned, runs, summary }
  ```
  `summary` holds `{ n, top1Rate, top2Rate, inconclusiveRate, unverifiedPostedTotal, droppedTotal, errorCount, medianMs, p95Ms, inputTokens, outputTokens, perScenario: { [id]: { n, top1, top2, inconclusive } } }`. Rates are rounded to 4 decimals.
- When `model` is passed it is used; otherwise `createModel(modelSpec, env)`.

**`fabricationBench.ts`:** `runFabricationBench({ repeat, outFile })`:
1. For each scenario and repeat, create a fresh `FabricatorModel(new HeuristicModel(), { seed: 1000 + r })` and run the pipeline as above.
2. For each `log.fabricated` summary, it is **blocked** when it is in `report.dropped` and not in `report.posted`. An honest summary is **kept** when it is in `report.posted`.
3. Write `{ schema: 1, env: "local-fixture", fabricatedInjected, fabricatedBlocked, byKind: { char|row|query|field: { injected, blocked } }, honestInjected, honestKept, unverifiedPostedTotal, runs }`.

**CLI:**
- **`rca eval run --model <spec> [--scenarios all|id,id] [--repeat 3] [--out bench/results/eval-<slug>.json]`** prints a progress line per run, `[i/total] <scenario> seed <s>: <status> top1=<✓|✗> <ms> ms`, then a summary table with these rows:
  - top-1;
  - top-2;
  - inconclusive;
  - unverified posted;
  - median ms;
  - tokens.

  It returns 0 even when accuracy is low. It returns 1 only when `unverifiedPostedTotal > 0`, because that is the invariant.
- **`rca eval fabrication [--repeat 3] [--out bench/results/fabrication.json]`** prints the blocked and kept ratios. It returns 1 when `fabricatedBlocked < fabricatedInjected` or `unverifiedPostedTotal > 0`.
